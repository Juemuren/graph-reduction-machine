## 第二版：Playground（暂缓）

第二版要求可以在浏览器中编辑代码、使用编译器和解释器、查看运行结果。

### 第二版暂缓原因

- GHC WebAssembly 工具链仍处于技术预览阶段。
- Windows 上没有可用的交叉编译工具，需要调整本地开发环境。

### 第二版预计路线

1. 做 WebAssembly 可行性的本地验证
2. 实现完整编辑器界面。可以使用已有的成熟的 Web 编辑器
3. 在 CI 中实现集成

参考信息:

- [GHC WebAssembly 指南](https://ghc.gitlab.haskell.org/ghc/doc/users_guide/wasm.html)

### 第二版功能范围

编辑器界面包含：

- λ/SKI 源码编辑区
- 阶段选择
- 编码与解码选项
- 运行按钮
- 解码结果、错误和归约步数

编辑器考虑增加会话功能：

- 同一会话中的文件按相对路径解析
- 示例页可用 `在演练中打开` 将源码和相关导入文件导入到编辑器会话中

关于运行功能：

- 放在 Web Worker 中
- 提供归约步数上限的设置
- 可以手动取消
- 设置单次运行的时间和内存边界，并处理超出边界的情况

### 第二版验收条件

- 示例可以一键载入。
- 能完成 `源码 -> 编译 -> 解释 -> 结果` 的完整流程。
- 错误能定位到当前阶段。
- 文件导入和标准库能工作。
- 页面在长时间计算时仍可操作。

## 第三版：LSP（暂缓）

第三版在第二版的编辑器和虚拟文件基础上加入语言服务。

### 第三版暂缓原因

- 语言服务器需要接入第二版实现的编辑器，因此要等待第二版完成。

### 第三版预计路线

1. 验证语言服务器核心能否构建为 WASM
2. 复用已有模块中的分析逻辑
3. 把语言服务器接入第二版实现的编辑器。可以使用已有的成熟的 Web 编辑器 LSP 客户端

### 第三版功能范围

让浏览器中的核心 λ 和 SKI 图的编辑体验覆盖现有语言服务器的主要功能。

具体功能见 [语言服务器文档](lsp.md)。

多文件能力可能需要根据第二版的实现情况进行调整。

### 第三版验收条件

- 对核心 λ 和 SKI 图提供与现有语言服务器功能一致的语言服务。
- 重命名和签名提示等现有功能在适用语言中可用。
- 跨文件导入的悬停和跳转可定位到会话中的文件。
- 编辑器与现有命令行语言服务器对相同测试样例给出一致的关键结果。
- 长文件或频繁输入时页面保持可操作。

## 第四版：Benchmark（暂缓）

### 第四版暂缓原因

- 在网页中重新运行 Benchmark 必须先有第二版的编译与解释接口
- 现有的 Python 比较脚本不能直接放到静态网站运行，需要用 TypeScript 或 JavaScript 重写
- 现有的比较图表和数据第一版已经实现了展示，因此在线 Benchmark 的重要性偏低

### 第四版预计路线

把现有的 Python 比较脚本的主要功能用 TypeScript 重写：

- 读取并解析 JSON 配置：Web 侧要使用相同的 JSON Schema
- 生成入口表达式、逐点测量、检查同一输入的结果是否一致：Web 侧按原有语义重新实现
- 子进程调用、磁盘读写、Matplotlib 绘图：Web 侧要改用 Playground 的运行接口、浏览器下载、JavaScript 绘图库
